# Release 2026-09-12

This release fixes inflated current hashrate readings at Search statistics
window boundaries and prevents the last Search rate from remaining visible
during a foreground Dataset build or reconnect.

The previous calculation divided all completed nonces in a command group by
only its contribution to the cumulative active-time union. Overlap with the
previous group could leave a few microseconds as the denominator. A synthetic
depth-four regression reproduced approximately 56.81 billion H/s. The
historical JSONL file contains no individual command timestamps, so its exact
command windows cannot be reconstructed.

Current hashrate now divides the group's nonces by the union of the complete
submission-to-completion intervals of those same commands. A group contains
16 commands, or the remaining commands on flush. Queue latency is included;
short final groups can therefore report lower rates than the active average.
No hashrate ceiling is applied. A window with no positive duration reports zero.
The current rate is zero outside `searching` and stays zero after Search resumes
until its first new measurement.

Cumulative nonces still count every completed nonce once, and cumulative active
time counts overlapping intervals once. Active-average hashrate, effective
session hashrate, Search duty, GPU time, donation attribution and expected
share accounting retain their semantics. Dataset and idle gaps remain part of
elapsed session time. Mining kernels, scheduling, tuning and share processing
are unchanged. The embedded Metal library is byte-for-byte identical to the
7 September release.

## Validation

- 93 Debug tests and 93 optimized Release tests passed, with no failures or
  skips. The 11 added tests include depths 1–4, every partial-window size 1–15,
  overlap across window boundaries, nested/out-of-order completion intervals,
  repeated flushes, job changes and drains, Dataset transitions, idle gaps,
  zero durations, variable nonce counts, donation and serialized telemetry.
- The production executable is built separately from tests, with Swift `-O`,
  whole-module optimization and no testability override. Metal uses fast math
  with no debug/source-recording flags. The executable is arm64-only, includes
  `__TEXT,__metallib`, contains no `__DWARF` or source/function debug symbols,
  and links only system libraries.
- Apple's `strip` retains its `N_OPT` compatibility marker `radr://5614542`.
  This contains no source debugging information; its purpose is documented in
  [Apple's strip implementation](https://github.com/apple-oss-distributions/cctools/blob/main/misc/strip.c).
- Developer ID signing includes Hardened Runtime and a secure timestamp.
  Strict signature validation passed. Apple notarization returned `Accepted`,
  `Ready for distribution`, no issues, and a ticket matching the binary CDHash.
- Gatekeeper recognized the code as valid after ticket propagation, with its
  expected bare-command-line-tool assessment. The extracted executable passed
  device discovery, the independent Autolykos replay fixture and the packaging
  script's isolated Metal smoke benchmark.
