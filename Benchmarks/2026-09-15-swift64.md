# Swift 6.4 / Xcode 27 migration

## Changes under measurement

BLAKE2b chaining state, compression words, working state and permutation tables
now use `InlineArray`. UInt256 stores its eight words inline while retaining
the public array property and the `{"limbs":[...]}` JSON representation.
Its decoder rejects arrays with any width other than eight. The Metal encoder
copies the two fixed argument blocks directly into command storage.

Swift 6.4's safe `RawSpan.load` reads whole words without raw pointers or manual
byte assembly. Explicit `UInt32(bigEndian:)` and `UInt64(littleEndian:)` retain
the macOS 26.5 deployment target: the SDK's new byte-order overload requires
macOS 27. MiningWork forwards stored job fields through `borrow` accessors.
The explicit outer Stratum closure capture preserves its existing strong
ownership while the connection's long-lived callback remains weak.

GPU capture methods, references to Metal capture classes and CLI options are
excluded from Release with a build condition. Debug and Profile retain capture.
The normal benchmark, replay, status API and operational telemetry remain
available in the production executable. GPU kernels and tuning defaults are
unchanged.

Relevant language references:

- [SE-0507: borrow and mutate accessors](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0507-borrow-accessors.md).
- [SE-0525: safe RawSpan loading](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0525-rawspan-safe-loading-api.md).
- [SE-0453: InlineArray](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0453-vector.md), available since Swift 6.2.
- [Apple's Xcode 27 release notes](https://developer.apple.com/documentation/xcode-release-notes/xcode-27-release-notes).

## CPU comparison

Apple M4 (Mac16,1), 32 GB unified memory; Xcode 27.0 (27A266a), Apple Swift
6.4 (swiftlang-6.4.0.34.1), Swift 6 language mode, `-O` and whole-module
optimization. Both versions use this same compiler. The baseline consensus
sources are from `3e024cc4da34ac21c178be3256c08195ab436e0c`.

The standalone [harness](../Scripts/benchmark-consensus.swift) runs three ABBA
cycles: baseline, candidate, candidate, baseline. Each workload has six samples
per version. Inputs vary on every iteration and a printed checksum consumes
the result. Checksums match in every comparison. Times below are medians.

| Workload | Iterations/sample | Baseline | Candidate | Speedup |
|---|---:|---:|---:|---:|
| BLAKE2b, 32 bytes | 262,144 | 85.36 ms | 48.31 ms | 1.77x |
| BLAKE2b, 128 bytes | 262,144 | 113.42 ms | 49.70 ms | 2.28x |
| BLAKE2b, 8,200 bytes | 8,192 | 191.29 ms | 52.78 ms | 3.62x |
| Full Autolykos CPU hit verification | 256 | 195.97 ms | 56.82 ms | 3.45x |

The 8,200-byte input matches a Dataset element's 8-byte prefix plus constant M.
The hit workload uses height 614,400 and a 1,024-element table index space;
the CPU still computes each referenced element from the complete constant M.
The measured CPU cost per hit falls from approximately 766 to 222 microseconds.
These are CPU verification results, not GPU mining hashrates.

To reproduce the candidate harness from the repository root:

```sh
xcrun swiftc -swift-version 6 -target arm64-apple-macos26.5 \
  -O -whole-module-optimization \
  Sources/MetalErgoCore/Blake2b.swift \
  Sources/MetalErgoCore/UInt256.swift \
  Sources/MetalErgoCore/Autolykos.swift \
  Scripts/benchmark-consensus.swift -o /tmp/ergometal-consensus-benchmark
/tmp/ergometal-consensus-benchmark
```

Use the same harness with the three baseline source files for the other side
of the comparison. This harness is not linked into the distributed executable.

## Full Dataset GPU comparison

The baseline here is the published 12 September notarized executable, built
with Xcode 26.6 / Swift 6.3.3. The candidate is a separate production Release
build with Xcode 27 / Swift 6.4 and no testability override. This comparison
therefore includes both source and compiler changes.

Eight sequential runs use a 6,925,769,760-byte consensus Dataset at height
1,841,500. Each builds the Dataset from scratch and then searches for 20
seconds. A start gate requires the maximum reported SoC die temperature to be
at most 55 C. All eight execution values are fixed explicitly; autotuning and
prebuild are disabled.

The first ABBA cycle is retained as preparation data and excluded from the
reported medians: a small replay smoke check overlapped its first candidate
run. The reported comparison uses the second, isolated ABBA cycle. No builds,
tests or other GPU commands were run during that cycle.

```sh
ergometal benchmark --duration 20 --height 1841500 --profile peak \
  --autotune off --prebuild off \
  --batch-nonces 1048576 --prebuild-batch-nonces 65536 \
  --threadgroup-size 128 --dataset-threadgroup-size 32 \
  --build-chunk-elements 2097152 --prefetch-chunk-elements 2097152 \
  --search-pipeline-depth 4 --build-pipeline-depth 2 \
  --dataset-kernel u32pair-inline-m --dataset-scheduling overlap \
  --search-kernel search --api-bind 127.0.0.1:0 --json
```

| Metric (median, two samples/version) | Previous release | Candidate | Change |
|---|---:|---:|---:|
| Dataset build | 30.337 s | 30.332 s | -0.02% |
| Active search rate | 15.274 MH/s | 15.148 MH/s | -0.83% |
| Effective session rate | 6.081 MH/s | 6.037 MH/s | -0.71% |

All runs ended in the nominal thermal state. Effective session rates include
one roughly 30-second cold build plus a 20-second search window; they are not
steady-state pool rates. The isolated comparison shows approximately 0.83%
lower active search throughput and almost identical Dataset time. This small
sample establishes no GPU performance improvement. It does not justify a
change to kernels, scheduling or autotuning defaults.

[Raw measurements and input identities](2026-09-15-swift64-results.json) retain
both preparation and measured runs. Only the M4 on macOS 27 was exercised;
other Apple GPUs and execution on macOS 26.5 were not tested. No live pool or
share-profitability comparison was performed.

## Correctness and production checks

96 Debug and 96 optimized Release tests passed, with zero failures and no
skipped tests. Coverage includes independent BLAKE2b block-boundary vectors,
the official Autolykos vector, CPU/Metal agreement, UInt256 byte widths and
JSON compatibility, pipeline cancellation, Stratum and cumulative telemetry.
There are no Swift source warnings. Xcode emits its informational AppIntents
metadata-extraction warning for the two test bundles, which do not use that
framework. The benchmark shell regression also passed.

The production executable is built separately with testability disabled,
Swift `-O`, whole-module optimization and no Swift or Metal debug information.
GPU capture classes are absent from the binary and its capture CLI options are
rejected. See the [release record](../Releases/2026-09-15.md) for signing,
notarization and artifact identities.
