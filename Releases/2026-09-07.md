# Release 2026-09-07

Mining now resumes an interrupted cold Dataset build when the next pool job
has the same height and table size. Completed GPU chunks survive a reconnect;
the remaining chunks finish before Search can use the Dataset. A different
height or table size discards the incomplete buffer. Old pool jobs remain
invalid after reconnection.

The solver retains at most one incomplete private buffer, only after all
submitted GPU commands have drained successfully. GPU failures prevent reuse,
and a new prefetch discards the retained buffer before allocating its own.
Benchmark and autotuning builds keep their previous cancellation behavior.
JSONL and Prometheus expose resumed-attempt and reused-element counters.
Build accounting includes each attempt once and excludes the reconnect pause
from the Dataset's cumulative build time.

The autotuner adds 32 to its Dataset threadgroup candidates, alongside 64,
128, and 256. Search candidates and conservative fallback values are unchanged.
SIMD/pipeline validation, the bounded startup budget, exact consensus checks,
and the 2% ABBA improvement gate still apply. The candidate policy uses
autotuning algorithm version 2; binary SHA-256 separates the new executable's
cache entries from previous releases.

The embedded Metal library is byte-for-byte identical to the 5 September
release. This release changes build control and candidate selection without
changing the hash kernels.

## Validation

- 82 tests passed in Debug and 82 in optimized Release, with no failures or
  skipped tests. Release tests explicitly enable testability; packaging builds
  a separate executable without that override.
- Tests cover exact resumed Dataset contents at pipeline depths 1 through 4,
  the 32-thread pipeline, repeated interruptions, height/size mismatch,
  cancellation before submission, opt-out, cumulative timing, and a simulated
  coordinator reconnect that invalidates the old job while reusing its Dataset.
- The benchmark campaign driver regression and shell syntax checks passed.
- All 16 measured full-size builds completed successfully. The paired gain
  for 32 threads was only 0.212%, so the 256-thread fallback remains unchanged.
- The released autotuner exercised the new 32-thread candidate with the other
  seven execution values fixed, completed in 7.128 seconds, and correctly
  retained 256 because no candidate met the improvement gate.
- A local Stratum reconnect during a full-size build reused 46,137,344 elements.
  Exactly 109 build commands constructed the entire Dataset across both
  attempts; Search resumed and SIGINT produced one complete final event.
  See [the measurement report](../Benchmarks/2026-09-07-m4-build-threadgroups-and-resume.md).
- The packaged executable passed the isolated Metal smoke benchmark and the
  independent Autolykos replay fixture.
- Swift uses `-O` and whole-module optimization. Metal uses
  `-fmetal-math-mode=fast` and `-fmetal-math-fp32-functions=fast`, with no debug
  or source-recording flags. The stripped executable is arm64-only, embeds
  `__TEXT,__metallib`, has no `__DWARF` segment or debug symbol entries, and
  links only system libraries.
- Developer ID signing with Hardened Runtime passed strict verification.
  Apple notarization returned `Accepted`, `Ready for distribution`, and no
  issues. The ticket's CDHash matches the executable; Gatekeeper recognizes
  the notarized code as valid, with the expected bare-command-line-tool result.
