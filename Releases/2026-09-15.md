# Release 2026-09-15

This release adopts Xcode 27 / Swift 6.4 for CPU consensus verification and
Metal argument preparation. BLAKE2b and UInt256 use fixed-size inline storage;
safe RawSpan word reads replace manual byte assembly; MiningWork exposes stored
job fields through borrow accessors. The UInt256 array API and JSON shape are
preserved, and malformed decoded limb counts are rejected.

The M4 CPU comparison measures 1.77x to 3.62x faster BLAKE2b hashing and 3.45x
faster complete Autolykos hit verification. The isolated full-Dataset comparison
measures 15.148 MH/s active Search versus 15.274 MH/s for the previous release
(-0.83%), with approximately 30.33 seconds for Dataset construction in both
versions. This short comparison establishes no GPU performance improvement.
See the [benchmark report and raw data](../Benchmarks/2026-09-15-swift64.md).

GPU capture methods and their CLI options are compiled out of Release. They
remain available in Debug and Profile. The packaging script rejects a Release
binary that still references Metal capture classes. Operational benchmark,
replay and telemetry commands remain available. The new compiler's Stratum
closure-ownership warning is resolved with an explicit existing strong capture;
the connection's callback retains its weak ownership.

Kernel sources, scheduling, tuning defaults, donation policy and cumulative
telemetry semantics are unchanged. The Metal library is rebuilt with Xcode 27.
The deployment target remains macOS 26.5 on Apple Silicon, with Swift 6 language
mode and complete strict concurrency checking.

## Validation

- 96 Debug and 96 optimized Release tests passed, with zero failures or skipped
  tests. Added coverage includes independent BLAKE2b vectors at word/block
  boundaries, all UInt256 byte widths, value semantics, overflow and JSON
  compatibility. Existing CPU/Metal, cancellation, Stratum and telemetry tests
  passed. The benchmark shell regression passed.
- The production executable is built separately from tests with Swift `-O`,
  whole-module optimization, testability disabled and no Debug/GPU_CAPTURE
  compilation conditions. Metal uses fast math and no debug/source-recording
  flags. There are no Swift source warnings.
- The archive contains one executable with its execute permission preserved.
  It is arm64-only, embeds `__TEXT,__metallib`, has no `__DWARF` or source/function
  debug symbols, and links only system libraries. Apple's `strip` retains the
  `N_OPT` compatibility marker `radr://5614542`.
- Strict Developer ID signature validation passed, with Hardened Runtime and a
  secure timestamp. Apple notarization returned `Accepted`, `Ready for
  distribution`, no issues, a ZIP hash matching the archive and a ticket CDHash
  matching the executable.
- Gatekeeper recognizes the notarized code as valid, with its expected
  bare-command-line-tool assessment. The packaging script now bypasses stale
  assessment-cache entries when checking the newly issued ticket.
- The packaged executable passed device discovery, the independent replay
  fixture and the isolated Metal smoke benchmark. Its `__TEXT,__text` and
  `__TEXT,__metallib` sections are byte-for-byte identical to the benchmarked
  production build. Production help excludes GPU capture, and capture options
  are rejected.

Runtime verification covers this M4 on macOS 27. Other GPUs and runtime behavior
on macOS 26.5 were not tested. The signed executable grows from 1,155,408 to
1,171,088 bytes; the measured benefit is lower CPU verification cost and fewer
working allocations.
